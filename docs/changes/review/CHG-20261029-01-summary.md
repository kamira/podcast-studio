## 3. 跨 task 的共同問題

1. **整合分支帶著舊草稿(RS-7)**:T1~T6 施工分支在草稿定稿前 merge 了草稿分支,之後草案 PR #98 以 squash 合入 main,整合分支既沒有 main 的定稿 commit、又保留舊草稿的檔案版本。程式依定稿施作,文件卻退回;合併 PR 會在 5 個檔案衝突。修正方式是把 `origin/main` 合入整合分支並以 main 定稿為準(M-1)。之後的 CHG 建議:草稿未合入 main 前不開施工分支,或施工分支不 merge 草稿分支(列入 §6)。
2. **施工偏離只記在派發者回報、未寫入 CHG(RS-11、RS-12、RS-17~RS-20)**:多個 task 的測試目標或範圍與定稿不同,只在派發記錄或施工者回報裡帶過。凡與定稿 task test 文字不同者,須在 CHG 派發記錄逐項補記「定稿寫什麼、實際做什麼、原因」;改變使用者核准的畫面行為者(RS-18)交使用者決定。
3. **帳本狀態落後(RS-8、RS-9)**:派發記錄 PR 欄與「## 狀態」都停在施工前。
4. **前後端資料來源不一致的邊界情況(RS-5、RS-16)**:長度與音源、詞庫是否存在的判斷各自取不同來源;修正時以單一來源為準(後製是否有效以「資料相符且檔案存在」判斷;詞是否存在以完整詞庫判斷)。
